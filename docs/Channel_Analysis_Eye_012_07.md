# SParamView v1.4.0 — 012_07 Eye Numerical Engine Contract

**Status:** implementation branch / independent CI qualification pending. **Scope:** 012_07 **Qt-free** C++20 engine and numerical tests only. The independent Qt window, editable settings, plots, CSV/PNG, async worker/source-snapshot integration are **012_08**. This is not a v1.4.0 release.

## 1. Eye definition and profile selection

The built-in **MIPI D-PHY HS example** sets **4.5 Gb/s per lane**, **2.25 GHz reference marker** (NRZ Nyquist), and a separate **10 GHz analysis upper limit**. The **NRZ reference frequency is defined as bitRate/2**, not a decorative marker. Updating the reference via `eyeWithReferenceFrequency` **also changes the bit rate and UI**, and contradictory values fail closed. The **analysis cap is independent** of this coupled clock/bit-rate setting. The symbol interval is 1 / 4.5e9 = **222.222... ps**. Sample rate is `bitRate × samplesPerUI`; the reference is coupled to bit rate, never the Touchstone maximum.

Profiles: **MIPI D-PHY HS, DDR2, DDR3, DDR4, DDR5, LVDS, SLVS, SLVS-EC, Custom**. Apart from the documented MIPI *rate/marker/cap example*, presets intentionally do **not** invent data rates, TX output swings, source impedance, receiver termination, common mode, receiver input range, or threshold. These are user- and topology-specific and in some cases require licensed standards, vendor IBIS/AMI or receiver characterization. No chosen preset proves the selected mode/voltages/timing are standards-conformant.

`eyeProfile(EyeProfile)` returns a fully named profile. For the seven other named PHY groups and Custom, rate, marker and analysis cap require the user to enter physical values. A missing required input fails closed with `si::Error` rather than selecting a guessed PHY value.

## 2. Numerical and electrical modeling

- Input must be a **confirmed THROUGH** `S21/S12` (single-ended) or `Sdd21/Sdd12` (differential) complex trace, with explicit physical port-mode and strictly increasing nonnegative frequencies.
- **Measured DC (0 Hz) and measured coverage through the requested analysis cap are mandatory.** No DC guess, held-last-value, S-parameter extrapolation, or phase substitution.
- **Electrical input contract:** TX incident low/high voltages at the two-port reference plane; source impedance; receiver termination; RX decision threshold; RX *linear input operating range*. All must be explicitly supplied, finite and logically valid. The engine requires a matched, equal-real-Zref source/THRU/receiver to use power-wave S21 as a voltage-wave ratio. It **does not support** unequal reference impedances, source/load mismatch, de-embedding, arbitrary Thevenin launch, common-mode conversion or an automatic mismatch correction. These conditions are errors, not approximation warnings.
- FFT model: uniform frequency grid `df = sampleRate/fftLength`, complex rectangular interpolation inside measured passband, conjugate-Hermitian mirroring of the positive spectrum, and deterministic **ideal zero response above the selected analysis cap**. The last operation is a modeling assumption, *not* knowledge of the unmeasured physical transfer. It is called out as `IDEAL_BAND_LIMIT` when applicable; it is not an S-parameter extrapolation or certified physical high-frequency model.
- Time response: inverse FFT of the modeled transfer, and the response to a one-unit-interval pulse. Input NRZ bit sequence is a deterministic periodic PRBS7 / alternating / user-provided binary sequence. TX waveform is an ideal instantaneous-step signal; an actual TX edge model, statistical jitter, bounded equalizer, receiver noise or arbitrary PHY TX/RX model is **not** inferred. Received waveform is periodic circular convolution with the modeled transfer.
- Eye metrics: for all phases across one UI, sample highs and lows after accounting for the modeled dominant impulse delay, compute **min(high) − max(low)**, choose its maximum phase, and measure the longest contiguous sampled interval satisfying min(high) > RX threshold > max(low). `eyeHeightV` may be negative, representing a closed eye. `eyeWidthUI`/seconds use discrete sample phases; these are deterministic *pattern-dependent* estimates, not probabilistic projections.
- The receiver operating range must contain all simulated received voltages; otherwise the linear transfer model is no longer valid and the result fails closed.
- Length must be a bounded power of two (1024..65536), samples/UI a power of two (8..128), at least 32 symbols; the sampled Nyquist must cover the requested upper cap. User-specified custom bits must be binary and include enough occurrences of both levels. Computation respects explicit cancellation checks.
- `Status::Warning` and `SIMULATED_ONLY` always accompany the generated numerical eye. Additional diagnostics identify bandlimiting, precursor energy, gain above unity, and closure. **No PASS/FAIL eye mask, MIPI/DDR/LVDS/SLVS PHY compliance, statistical BER, receiver equalizer, measured eye, or physical instrument accuracy is claimed.**

## 3. Source integrity and 012_08 boundary

`calculateEye(trace, settings, provenance, cancelled)` computes a trace already supplied and validated by its caller. In the Qt integration stage, `012_08` **must** capture `SourceSnapshot` (SHA-256-validated file/revision and confirmed mapping), call `extract(..., Metric::IL, ...)` from the shared Channel Analysis Core, bind `provenance`, and reject any stale source generation, re-mapping, cancellation, or unequal/misassigned port modes before displaying data. It must not bypass the electrical contract for preset convenience.

The dedicated 012_08 window will expose: profile, direction/mode, bit rate, coupled NRZ reference frequency/bit rate and independent analysis cap, TX low/high and matched source/load impedances, RX threshold/range, PRBS/alternating/custom sequence, FFT/sampling configuration, actual waveform and overlay, eye metrics, units, diagnostics, source revision and CSV/PNG export. Its screen must be prominently labeled **Simulated Channel Eye — Not Measured/Not Compliance**. The Eye menu remains unavailable until that GUI stage is implemented and qualified.

## 4. Numerical test evidence

Registered `channel_eye_numerics` tests: unity matched THRU with exact 0.4 V high-to-low eye, unit-width opening, identity time waveform; integer-sample complex-phase delay oracle (rejects magnitude-only transfer); half-gain and doubled-explicit-swing scaling; reference-frequency-driven bit-rate/UI change; band-limited cap warning; MIPI 4.5/2.25/10 example with explicit electrical inputs; single-ended and reversed THRU; missing voltage, incorrect/missing termination, RX threshold/range, DC and spectral coverage, nonfinite data, reflection mislabeled THRU, invalid FFT/pattern/rate, and cancellation rejection.
