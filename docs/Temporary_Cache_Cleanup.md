# SParamView v1.3.2 — temporary-data cleanup policy

This policy was introduced in **v1.2.5**, was retained for official **v1.3.0**, was further hardened for **v1.3.1**, and now includes project-scoped cleanup in **v1.3.2**. The cleanup changes do not delete user data. v1.3.0 additionally updates the binary cache schema so metadata generated by older parsers is not reused.

## Workspace-scoped cache retirement (v1.3.2)
- An independently leased GUI `session-XXXXXX` contains the current
  `workspace-XXXXXX` subtree. Touchstone revisions appended in the same
  workspace share its cache, allowing comparisons.
- **Open Project** stages a new subtree; it only replaces the active project
  after successful source verification and import. It then cancels or waits
  for viewport workers, releases previous jobs/Revision caches and clears
  stale comparison rows/plot axes/zoom before removing only its old owned
  workspace subtree.
- Invalid projects, source relocation cancellation and failed imports preserve
  the current project. New schema-1 project saves omit a stale `cache` path,
  but old project files with this unused property remain readable.
- Never delete an original Touchstone, project, export, settings or another
  live SParamView instance's separate leased session.
- `v124_gui_workspace_switch` checks A→B→A cache deletion, title/Revision
  update, same-window file append, previous plot/compare clearing, and failed
  project rollback.

## GUI cache ownership
- Each GUI window/process owns a unique directory inside the Qt application
  `CacheLocation/v3/session-XXXXXX` path.
- The imported `.sicache` and `.sicache.tmp` files are stored inside its
  private workspace subtree; GUI Excel report staging stays inside that
  unique owned session. The original Touchstone file is never modified.
- Graceful close waits for workers to complete, destroys any deferred
  QFutureWatcher callbacks, releases Revision/Job/cache references, then
  removes the owned directory. This matters on Windows where open file
  handles can prevent directory deletion.
- Cleanup also requires an exact SParamView ownership marker; folders that
  merely match the session naming pattern are not deleted.
- A lock-file lease prevents another instance from deleting a live session.
  The registry is locked during session creation, abandoned-session sweep,
  **and normal session shutdown deletion**; this prevents another process from
  reaping the same directory during its owner's exit. Time-only lease expiry
  is disabled. If the registry is busy or a file handle prevents deletion,
  shutdown defers cleanup to a future ownership-verified startup.
- After an abnormal termination, a subsequent launch attempts to remove
  sessions whose process-owned lease is no longer active.
- Files not inside session-XXXXXX, including old shared v3 caches produced
  by previous releases, are **not** removed automatically; legacy instances
  cannot provide a reliable live lease, so blindly deleting their files would
  risk disturbing a running old version.

## Retained user data
Original *.sNp/*.ts files, explicitly saved *.siproject files, XLSX/CSV/PNG
outputs, mapping/preset files, and QSettings are outside the owned session
directory and are never targets of cache cleanup.

## CLI
The default CLI cache uses a private command-scoped temporary directory,
removed when the CLI exits. If the caller explicitly supplies a cache
directory, that directory is treated as user-managed and is not deleted.
A forced termination may leave a CLI directory; it is not purged from the
shared OS temporary root without proof of ownership.

## Validation
- `session_cache_lifecycle`: real cache import, cleanup, concurrent leases,
  abandoned-session reclaim, unrelated files preserved, and symlink-target
  preservation.
- `multi_process_cache_isolation`: two real processes import the same two
  synthetic Touchstone inputs concurrently; independently release their
  caches; and recover a killed process's orphaned cache on later launch.
- Existing `v124_gui_*` cases (including `v124_gui_workspace_switch`) exercise loading, cache rotation and project restoration
  through the new scoped GUI cache path.
- `cli_session_cache_cleanup`: success, error path, and caller-managed CLI cache preservation.
- The v1.3.0 core, Windows x64/ARM64, native ARM64 packaged-binary and macOS Apple Silicon checks passed in [official CI](https://github.com/july-rust/SParamView-Public/actions/runs/40807027224).
