# 012_12 — IEEE 802.3ck-2022 Annex 120F COM 4.17 reference configuration and input qualification

**Scope:** executable reference-configuration contract and SHA-pinned input preflight. **Not a native SParamView COM numerical implementation.** This is a *single bounded development task*, not v1.4.0 release clearance.

## Verified source and contract

1. Work from the previously audited final published IEEE Std 802.3ck-2022 **120F.4.1 / Table 120F-8** C++ numeric profile. The private user-supplied licensed 316-page IEEE original was checked in **012_11**; all 68 existing numeric C++ leaves were matched. SHA-256 and printed pages 236–238 are recorded in [012_11 provenance audit](COM_8023ck_Normative_Audit_012_11.md). **The original PDF is not in this repository.**
2. `scripts/com_120f8_config_contract.py` extracts and independently verifies all 68 mapped leaves directly from `include/si/channel_analysis/com_120f8.hpp` against the prior independently authored source-value regression. A changed leaf, missing mapping or renamed field is **FAIL CLOSED**.
3. Emit an ephemeral COM-4.17-compatible CSV **without** bundling external COM software. Explicitly preserve **53.125 GBd** (not bit rate), GHz and ns config units, TX/RX package arrays, FFE/CTLE ranges, bounded DFE arrays, and `Port Order=[1 2 3 4]` *only for the exact SHA-verified 2019 historical IEEE S4P corpus*. The **one CSV contains both Test 1 and Test 2**; do not count it as two independently acquired profiles.
4. Test 1 package primary line: **TX 13 mm / RX 11 mm**. Test 2: **TX 31 mm / RX 29 mm**. The input package matrices encode both cases as distinct columns and are transposed by the pinned independent reference reader into case-major rows. The optional secondary line remains **1.8 mm**.
5. One chosen COM-4.17 compatibility value, package `gamma0=0`, is **not source-qualified from the 68 final IEEE numeric leaves**. Similarly a stand-alone receiver termination/vector representation, `FORCE_TR`, `RESULT_DIR`, `Include PCB`, `z_p select` and a historical source-specific port map are *adapter choices, not additional published-standard parameters*. These choices are recorded and must never silently qualify an IEEE normative engine. NEXT/FEXT aggressor package source+role configuration remains **NOT_QUALIFIED**. To satisfy the independent parser's strict equal matrix shapes, CSV sets **explicit nonphysical zero-length NEXT/FEXT package sentinels** and `NO_COM=1`, making this file **configuration-loading QA only, NEVER a physically valid input for COM numerical optimization**. A future numerical solver must provide independently justified nonzero aggressor topology before enabling calculations.
6. The standalone static check returns `STATIC_CONTRACT_PASS` only for serialization/identity. If the independent parser was actually executed and passed it additionally returns `RUNTIME_LOAD_PASS`. Without execution, its status is `NOT_RUN`; never infer success from file generation. The **official COM 4.17 MATLAB source is not executed** by the pinned independent SiCoPR parser.
7. The SHA-pinned public **2019 IEEE historical C2C archive** is only an **input provenance** fixture, **not a published-final normative IEEE 802.3ck Golden channel suite**. Three original THRU/FEXT/NEXT member groups (10/16/18 dB historical loss labels) are verified by exact ZIP and individual S4P SHA-256 in disposable GitHub Actions runner storage. Four repeated copies of one FEXT per historical group are **not four independent original FEXT measurements**. The `INPUT_SHA_PASS` label does not mean COM passed, nor that final-profile channel packaging/causality or independent COM margins have been calculated.
